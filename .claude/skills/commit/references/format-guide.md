# Conventional Commits フォーマットガイド

## タイトル（1行目）

```
<type>: <日本語の簡潔な説明>
```

### type の種類

| type | 用途 |
|------|------|
| `feat` | 新機能の追加 |
| `fix` | バグ修正 |
| `refactor` | リファクタリング（機能変更なし） |
| `docs` | ドキュメントの変更 |
| `style` | コードスタイルの変更（フォーマット等） |
| `test` | テストの追加・修正 |
| `chore` | ビルド、CI、依存関係など雑務 |
| `perf` | パフォーマンス改善 |

### ルール

- タイトルは **70文字以内** を目安にする
- 「何をしたか」を簡潔に書く

## 本文（任意）

変更が大きい場合（複数ファイル、複雑なロジック変更）のみ本文を付ける。

```
<type>: <タイトル>

<なぜこの変更が必要か、何を変更したかの詳細>
```

- 小さな変更（1-2ファイル、単純な修正）はタイトルのみで十分
