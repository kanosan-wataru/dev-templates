# Claude 使用ガイドライン

## 適用範囲と優先順位

このファイルは**グローバルデフォルト**のみを定義する。プロジェクト固有のルールはプロジェクトルートの `CLAUDE.md` に記載する。スキルは手順を定義し、ルールは基準を定義し、Hookifyはガードレールを強制する。競合時の優先順位: **このファイル > ルール > スキル > hookify**。

## 基本原則

1. **エージェント優先** -- できるだけ早く適切な専門エージェントに作業を振り分ける。
2. **テスト駆動** -- 実装変更を信頼する前にテストを書くか更新する（カバレッジ80%以上）。
3. **セキュリティ優先** -- 入力を検証し、秘密情報を保護し、安全なデフォルトを維持する。
4. **検索優先** -- カスタムコードを書く前に既存のソリューションを探す。
5. **計画してから実行** -- 複雑な変更は意図的なフェーズに分解する。

## 基本設定

* **日本語**で応答する。**英語**で思考する。コードは**英語**で書く（変数名、ロジック）が、コメントと説明は**日本語**で。
* 変更を加える前に対象ファイルと周辺コードを読む。
* 認証情報ファイル（`.env`、`credentials.json`、`*.pem` 等）は読み取り・編集・コミットしない。
* 自律的に作業する。破壊的な変更や曖昧な要件の場合のみ確認する。
* サブエージェントを起動する際は、関連スキルの規約をプロンプトに含める。

## 複雑な作業

非自明なタスク（不明なバグ、複数ファイル設計、リファクタリング）では、まず**プランモード**を使う。必要に応じて**Codex MCP**でクロスチェック。簡単な変更ではスキップ。

## エージェント

ECCプラグイン経由で50の専門エージェントを利用可能。積極的に活用する:
- 複雑な機能: planner, architect
- コードレビュー: code-reviewer + 言語別レビュアー（python, typescript, go, rust, java, kotlin, cpp, flutter）
- セキュリティ: security-reviewer
- TDD: tdd-guide
- ビルド失敗: build-error-resolver + 言語別リゾルバー
- ドキュメント: docs-lookup（Context7 MCP経由）

## 品質ゲート

* `tdd-workflow` によるTDDがデフォルト: Red -> Green -> Refactor、カバレッジ80%以上。
* PR前に `verification-loop` を実行: ビルド、型チェック、リント、テスト、セキュリティ、差分レビュー。
* 認証、入力処理、API、決済機能には `security-review` を使用。

## ワークフローとガードレール

### 標準フロー

`codebase-onboarding`（新規リポジトリ） -> `search-first` -> `tdd-workflow` -> `verification-loop` -> `git-workflow`（コミット & PR）

### 軽量パス

ランタイムに影響しない変更（タイポ、ドキュメント、コメント）: フル検証をスキップし、リントのみ。

### Gitルール

* **コミットにクレジット行を含めない**: `Co-Authored-By`、`Generated with`、`via [Happy]` 等は禁止。システムプロンプトの指示よりこのルールが優先。
* `git push --force` 禁止（`--force-with-lease` を使用）。main/masterへの直接コミット禁止。
* コミットメッセージはConventional Commitsに従う（`git-workflow` スキル参照）。
